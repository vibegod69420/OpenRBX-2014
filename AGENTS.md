## Current generation model

- Backend: `deepai` (`tools/deepai_backend.py`) → `https://api.deepai.org/deepai_code`.
- Model: `deepseek-v4.1-flash`, 320,000-token context, `reasoning_effort: "max"`.
- Key: `DEEPAI_API_KEY` in the environment, or `/etc/openrbx/deepai.env` on the worker.
  Never write it into a tracked file, a prompt, a commit or a log line.
- The harness defaults to this backend (`DECOMP_BACKEND=deepai`); `opencode`, `kaggle`,
  `kbench` and `local` remain available as opt-in alternatives.

## Autonomous non-stop loop

1. Never stop and wait for human confirmation during the decompilation loop.
2. Pick the next target with `python tools/next_target.py`, read it with
   `python tools/func_context.py <addr>`, implement in `Client/`, verify with
   `python tools/verify_tu.py Client/<subsystem>/<File>.cpp <addr>`, then publish with
   `python tools/update_progress.py --commit "..."` (add `--push` only when the worker
   has a git credential; `DECOMP_PUSH=1`).
3. Verification must run under MSVC 11.0 (`cl 17.00.50727`). Check it first with
   `python -c "import sys; sys.path.insert(0,'tools'); import verify_tu; print(verify_tu.get_compiler_version())"`
   and treat any other version as untrustworthy. On the Linux worker that compiler runs
   under Wine through `tools/msvc110-cl`, found via `MSVC_BIN_DIR` (`/opt/msvc110/bin`).
4. Generated bodies stay `// STUB:` until verified; only a measured 100.00% may promote a
   marker to `// FUNCTION:`. The harness does that itself — never do it by hand.
5. If a build or diff step fails, read the compiler/disassembly output, fix the cause and
   retry. Do not weaken the comparison to make a body pass.
